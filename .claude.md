# Muse — project context

Local macOS Electron app for collecting, organizing, and searching design reference — stills **and short video clips**. React 19 renderer, TypeScript everywhere, SQLite via better-sqlite3, plus a **bundled Ollama** for AI features (Qwen3-VL for vision/captioning, nomic-embed-text for caption embeddings; sqlite-vec for KNN, perceptual hash + palette indexing for visual signals) and a **bundled ffmpeg** for video decoding.

---

## Commands

| Command | Purpose |
|---------|---------|
| `npm install` | Install dependencies |
| `npm start` | Dev: Electron Forge + Vite (renderer hot-reload; restart for main/preload changes) |
| `npm run lint` | ESLint (`*.ts`, `*.tsx`) — the only check script |
| `npm run package` | Forge package (unsigned `.app`) |
| `npm run make` | Package + `MakerZIP` (darwin) + custom `postPackage` hook that builds `out/make/Muse-Installer-<version>-<arch>.pkg` |
| `npm run fetch:ollama` | Fetch/refresh the bundled Ollama engine into `resources/ollama/` (`--force` to re-download) |
| `npm run fetch:ffmpeg` | Fetch/refresh the bundled ffmpeg decoder into `resources/ffmpeg/` (`--force` to re-download) |

**Ollama is bundled and managed by the app, not the user.** `src/main/ai/ollama-server.ts` spawns a server on `127.0.0.1:11434` with `OLLAMA_MODELS` pointed at `userData/ollama-models`. Binary resolution: packaged → `process.resourcesPath/ollama/ollama`; dev → first hit among `resources/ollama/ollama` (the fetched engine), then `/opt/homebrew/bin/ollama`, `/usr/local/bin/ollama`. If a server is already running externally, the app attaches to it instead of spawning.

The engine is a **directory, not a lone binary** — `ollama` locates its runner and Metal libraries as siblings (`<exeDir>/llama-server`). Shipping only `ollama` produces a server that answers `/api/tags` (so every health check passes) but cannot run a model. `resources/ollama/` is gitignored and fetched at build time by `scripts/fetch-ollama.mjs`, pinned to a version + SHA-256 and verified before extraction.

Models (`qwen3-vl:8b-instruct` ≈6 GB, `nomic-embed-text` ≈274 MB) are pulled **in-app** on first run by `ModelSetup.tsx` via `ollama:pullModel` — no manual `ollama pull` needed.

**ffmpeg is bundled too, and is a lone binary** — unlike the Ollama tree, `resources/ffmpeg/ffmpeg` has no siblings to ship. Same resolution shape (`src/main/video.ts`): packaged → `process.resourcesPath/ffmpeg/ffmpeg`; dev → the fetched binary, then `/opt/homebrew/bin/ffmpeg`, `/usr/local/bin/ffmpeg`. ffprobe is deliberately **not** bundled: duration is parsed off ffmpeg's own stderr banner, and frame dimensions come from sharp reading an extracted (already auto-rotated) frame, which saves ~66 MB for metadata we get anyway.

The pinned build is **GPLv3 without `--enable-nonfree`**. That distinction is the whole reason for the pin: nearly every prebuilt macOS ffmpeg (including the `ffmpeg-static` npm package) is `--enable-nonfree` and cannot legally be redistributed at all. `fetch-ffmpeg.mjs` runs `-buildconf` after extraction and fails the build if that flag reappears.

## Architecture (data flow)

1. **Renderer** calls `window.electronAPI.*` (`src/renderer/lib/ipc.ts`).
2. **Preload** forwards via `ipcRenderer.invoke` / `on` (`src/preload/preload.ts`).
3. **Main** handles in `ipc-handlers.ts` and `index.ts` (dialogs, theme, update, log, drop echo).

**Library location:** `app.getPath('userData')/library/` — `library.db`, `originals/`, `thumbnails/` (created on demand by `getLibraryPath()`). Ollama models live beside it in `userData/ollama-models`.

**Staggered launch jobs** in `index.ts` (all non-fatal, all resumable next launch):

| Delay | Job |
|-------|-----|
| 5s | `backfillMissingPalettes` — palette rows for older imports |
| 8s | `upgradeEmbeddingIndexIfNeeded` — re-embed when the index format changes; reports through `embedding:progress` |
| 10s | `queueCaptionUpgradeIfNeeded` — re-caption images below `CAPTIONS_VERSION` through the normal AI queue |
| 12s | `checkForUpdate` — packaged builds only; silent, emits `update:available` |

## Schema (`database/schema.ts`)

`folders`, `tags`, `images`, `image_colors`, `image_tags`, `settings`, FTS5 `images_fts`, and vec0 `image_embeddings` (768-dim, nomic).

Migrated-in `images` columns worth knowing: `phash BLOB`, `alt_text`, `captions_version`, `duration_ms` (video only; NULL for stills and for clips whose container declares no duration), and the color index set `indexed_chromatic`, `indexed_hue_bucket`/`_2`, `indexed_hue_strength`/`_2`, `indexed_hue_degrees`.

**Videos live in the `images` table.** A video row is one whose original is a clip and whose `thumbnail_path` is an extracted poster frame; `width`/`height` are the poster's. Everything downstream — folders, tags, trash, colors, phash, embeddings, similarity — therefore works on videos with no special-casing. `isVideoFileType(file_type)` is the only test for "is this a video".

`smart_folders` and `ai_queue` exist in the schema but **nothing reads or writes them** — the AI queue is an in-memory array in `ipc-handlers.ts`. Don't assume DB-backed queue semantics.

## Conventions / pitfalls

- **Main vs renderer:** Changing `src/main/**` or `src/preload/**` requires a full app restart; the renderer hot-reloads via Vite.
- **Dropped files:** Paths must come from preload (`webUtils.getPathForFile`) — not from renderer-only APIs. The drop listener lives in preload, not React.
- **Dropped folders/zips:** `importFiles` is the single path-import entry point (drops *and* the file picker) and expands whatever it's given through `scanDropSources`. Folder structure is mirrored into Muse folders under the drop target, matching existing folders case-insensitively by name + parent. A dropped `.muse` is a zip but **not** a plain archive — it's returned in `summary.bundles` and forwarded on `library:import:dropped` so the library-import dialog keeps its tags, folders, and captions.
- **Local images:** `local-file://` is registered privileged (`bypassCSP`, `stream`, `supportFetchAPI`) and streamed from disk in `src/main/index.ts`.
- **Video is the one thing that does NOT use `local-file://`.** `ImageFocus` points its `<video>` at a plain `file://` URL. Chromium will not issue follow-up range requests to a custom protocol handler, so a clip served through `local-file` plays its first chunk and then dies with `MEDIA_ERR_SRC_NOT_SUPPORTED` the moment the demuxer reaches the moov atom at the end of the file — and `video.seekable` stays empty, so the scrub bar never works. Hand-rolling 206 responses in the protocol handler does *not* fix it (Chromium simply stops asking); Chromium's own file loader handles ranges natively, and the window already runs `webSecurity: false`. Posters and stills keep using `local-file://`.
- **Video captioning reads a contact sheet, not a frame.** `buildContactSheet` tiles 6 frames sampled across the clip into one 1536px-wide image, and `analyzeVideo` sends it *unscaled* (stills go at 1024) so each cell keeps ~512px and on-screen text stays readable. The prompt's real work is stopping the model from describing the grid — it names the frames as a filmstrip and bans the words "frames/panels/grid/collage" — so if you edit it, re-check that alt text still describes the clip rather than "a six-panel collage".
- **Video failure is an import failure.** A still whose thumbnail can't be generated still imports (SVGs rely on this); a video with no poster has nothing to render, so `persistImage` deletes the copied original and returns an error instead of storing an invisible row. Leaving the bytes behind would also make a retry look like a duplicate and skip itself.
- **AI queue:** One drainer in `ipc-handlers.ts`, fed by **two lanes**. `user` is work someone asked for (import, re-analyze) and is the only lane the progress toast counts; `background` is work the app decided to do on its own (the launch caption-upgrade sweep). New work extends the in-flight totals rather than starting a second drainer; counters reset only when the whole pipeline drains. Preserve all of that when adding AI work — and pick the right lane: putting a sweep in `user` makes the toast overstate what an import is doing, which is the bug the split exists to fix. User jobs drain first so the visible counter keeps moving, a job only broadcasts while its own lane owns the readout, and `enqueueAi` de-dupes against pending *and* in-flight ids (promoting a background id to `user` rather than running it twice).
- **Embeddings:** nomic requires task prefixes — corpus text uses `search_document: `, queries use `search_query: ` (`EMBED_DOCUMENT_PREFIX` / `EMBED_QUERY_PREFIX`). Mixing them silently degrades results and is what `upgradeEmbeddingIndexIfNeeded` exists to repair.
- **Caption generation:** Bump `CAPTIONS_VERSION` in `auto-tagger.ts` when the vision model or prompt changes — that's what triggers the launch-time re-caption sweep. Changing *only* the video prompt is not a reason to bump it: that would re-run a vision pass over an entire library of stills to fix captions on a handful of clips.
- **AI degradation:** Every AI path must stay optional; the app works with Ollama unavailable.
- **New menu items:** Add to `buildAppMenu()` in `index.ts`, forward through `onMenuEvent` in preload, and widen its channel union.
- **Preload isolation:** Preload must never import from `src/main/**` (it would pull in `electron.app`). Duplicate the type locally, as `UpdateInfo` does, or put it in `src/shared/`.
- **Starting the engine:** Always go through `ensureOllamaServer()`, never a bare spawn. It de-dupes concurrent starts behind one in-flight promise — the launch-time start and a renderer-triggered retry overlap routinely, and without it the second sees a still-starting server as wedged and kills it. It resolves `{ running, reason, detail }` rather than throwing, so every caller can explain the failure; `ModelSetup` / `ModelUpdateDialog` render `OLLAMA_FAILURE_MESSAGE[reason]`. Never report `ready` when the server is down.
- **Bundled engine:** Ship the whole `resources/ollama/` tree, not just the binary. `prePackage` fails the build if it's absent — a release once went out without it and left users with an unfixable "engine isn't running" dialog. The same guard covers `resources/ffmpeg/ffmpeg`; without it every video import fails at the poster step.
- **New columns on `images`:** add them to the `MIGRATIONS` array in `schema.ts` *and* to the explicit column lists in `library-import.ts` — the bundle importer enumerates columns by hand, so anything omitted there is silently dropped when a `.muse` library is imported. Bind `?? null`: older bundles have no such column and `SELECT *` yields `undefined`, which better-sqlite3 refuses to bind.
- **Shelling out via osascript:** Two levels of quoting that must not be conflated — quote the path for the POSIX shell, then quote the whole command as an AppleScript string literal (`shellQuote` / `appleScriptQuote` in `updater.ts`). Embedding double quotes in the shell command terminates the AppleScript string early and the script fails to compile (`-2740`).
- **Packaging:** `asar: false`, native modules rebuilt in `postPackage` against a hardcoded Electron version — bump it in `forge.config.ts` alongside the `electron` devDependency.

## When editing

Prefer extending existing repositories and IPC naming patterns. Keep thumbnail/color extraction non-fatal where already wrapped. Match the Zustand + `components/` layout rather than introducing parallel state layers unless necessary. Logic shared between main and renderer belongs in `src/shared/`.
